# YapCord

A client mod for **[Yapper](https://www.yapper.website/)** with a Vencord-style plugin, theme and settings system - for the desktop app, for Yapper in the browser, and on your phone.

YapCord puts a small runtime into Yapper before the page loads. That works in four ways: **inside the official Yapper app itself** (like Vencord in Discord: one app, you stay logged in), as a **stand-alone app** (its own Electron window that loads `yapper.website`, like Vesktop), as a **browser extension** for Chrome, Edge or Brave (see [Browser extension](#browser-extension-chrome--edge--brave)), or as a **[bookmarklet](#bookmarklet-any-phone-iphone-included)** that works on any phone's browser, iPhone included. The runtime gives you:

- a **Plugins page** inside Yapper's own settings window (on/off + options; everything starts off — you choose what to turn on; switching one only saves your choice, and a **Restart required** notice with a Reload button then explains that it takes effect after you reload);
- **themes** (`.theme.css`; 22 included) and **Custom CSS** (Vencord's QuickCSS);
- 78 plugins you switch on yourself (24 Vencord ports from 1.5.0, 8 more from 1.11.0, and more of our own — the full list is in [FEATURES.md](FEATURES.md#yapcord-plugins)), plus **49 always-on features of our own that just run, with no switch and no entry in the Plugins page** (see [FEATURES.md](FEATURES.md#always-on-features) for the full list);
- a **Layout page**: servers on the right instead of the left, move the columns around, make server icons / list width / text bigger or smaller, message spacing, and the zoom of the whole app;
- automatic updating, in the background and from a **YapCord → Updater** page (repo, auto-update and notify switches, manual check — see [Updating](#updating));
- in the stand-alone app also: system tray, start with Windows, screen-share picker, taskbar badge, its own file picker for the **+** button, and automatically closing the Yapper app while YapCord is open (inside the Yapper app, Yapper does all of that itself); backup/restore works in both.

> **Unofficial.** YapCord is not from Yapper and not from Vencord/Vendicated, and neither supports it. It only changes what your own app shows on your own computer; nothing is changed on Yapper's servers. Whether Yapper's terms allow modified clients is for you to check.

What of Vencord is and is not included is listed honestly in **[FEATURES.md](FEATURES.md)** (all 166 Vencord plugins).

## Quick start (Windows)

Pick one of the two ways. **Way 1 is recommended:** you do not have to log in again and there is only one app.

### Way 1: inside the official Yapper app (you stay logged in)

YapCord is then put *into* the Yapper app, the way Vencord does it for Discord. You start Yapper as always; the tray icon, the updates and the screen-share picker stay Yapper's. Your login is kept because the app stays the same (`%APPDATA%\Yapper` is not touched).

**With the installer (`YapCord-Installer-1.19.0.exe`, like the Vencord installer):**

1. **Quit Yapper completely**: right-click the Yapper icon next to the clock, then *Quit*. Closing the window is not enough, because Yapper keeps running in the system tray.
2. Start the `.exe`. You see your Yapper install (found in `%LOCALAPPDATA%\Programs`; if it is somewhere else, use *Choose another folder...*) and four buttons: **Install**, **Reinstall / Repair** (for example after a Yapper update), **Uninstall** and **Start Yapper**.
3. Click **Install**. Then just open Yapper (or click *Start Yapper*); the settings (gear icon) now have a **YapCord** section. You stay logged in.

The installer has the YapCord files inside it (you do not need internet, Node.js or npm to use it). It first checks whether Yapper is still running and does nothing if it is. You build the `.exe` yourself, see [Building the installer](#building-the-installer). **You can send the installer on its own** (no zip needed); everyone who runs it gets the YapCord version it was built from, and the Updater takes it from there.

**Without the installer (from the source, with Node.js):** quit Yapper completely (see above), open a terminal in this folder and run `node tools\yapper-patch.js install` (pass `--dir "D:\path\to\yapper-desktop"` if Yapper is not in `%LOCALAPPDATA%\Programs\yapper-desktop`). Then start Yapper; the settings (gear icon) now have a **YapCord** section.

**Undoing it:** quit Yapper completely and click **Uninstall** in the installer, or run `node tools\yapper-patch.js uninstall` from the source. Yapper is then exactly as it was; your YapCord settings stay in `%APPDATA%\YapCord`.

What the installer does (and nothing else): it copies YapCord to `%APPDATA%\YapCord\runtime`, renames Yapper's `resources\app.asar` to `_app.asar` (the original, unchanged) and creates a small folder `resources\app` that starts YapCord first and then Yapper's own code. Yapper's `.exe` and data stay untouched. If something fails halfway (for example because Yapper is still running), it puts everything back the way it was.

Good to know:

- **After a Yapper update YapCord is probably gone** (Yapper's updater replaces its files). Click *Reinstall / Repair* in the installer (or run `node tools\yapper-patch.js install` again from the source).
- **Protected Yapper versions:** if Yapper uses the Electron fuses `OnlyLoadAppFromAsar` or `EnableEmbeddedAsarIntegrityValidation`, Electron would ignore or refuse the change. The installer checks this beforehand and stops without changing anything. Only Way 2 works then.
- **What is not in the Yapper app:** the App settings of the stand-alone app (tray, start with Windows, own file picker, screen-share picker, closing the Yapper app). Yapper handles those itself. Plugins, themes, Custom CSS, backup and the right-click menus do work.
- Settings and themes live in `%APPDATA%\YapCord` and are shared with the stand-alone app.
- **If you also start the stand-alone YapCord app, it closes the Yapper app** (setting *Close the Yapper app*, on by default), and that is now the patched app. If you use Way 1, do not start the stand-alone app, or turn that setting off.

### Way 2: as a stand-alone app

1. Install **Node.js** (the LTS version) from <https://nodejs.org> if you do not have it yet.
2. Unzip this folder, open a terminal in it, and run `npm install` (first time only; downloads Electron, ~100 MB) and then `npm start`.
3. Log in to Yapper. You have to log in again: the stand-alone app keeps its own data, separate from your Yapper app.

> **Coming from the old name "YapperMod"?** On the first start of YapCord your old data folder `%APPDATA%\YapperMod` is renamed to `%APPDATA%\YapCord` automatically, so your settings, themes and login are kept. Quit the old app first. If moving fails (for example because the old app is still running), YapCord just uses the old folder as it is and moves it next time.

### Making a single `.exe` of the stand-alone app (optional)

```
npm install
npm run dist
```

That makes `dist\YapCord-1.19.0-portable.exe` (one file, no installation). You need internet because `electron-builder` downloads its parts. If Windows gives the error *"Cannot create symbolic link"*, turn on **Developer Mode** in the Windows settings or start the terminal as administrator. The `.exe` is not digitally signed, so SmartScreen may show a warning.

### Building the installer

```
npm run dist:installer
```

That makes `dist\YapCord-Installer-1.19.0.exe` (one file). You need Node.js and internet (`electron-builder` downloads its parts); `npm install` is not needed. The build script (`tools\build-installer.js`) puts the installer window (`installer\`) and the YapCord files into one folder and builds the `.exe` from that. Like the other `.exe`, this file is not signed, so SmartScreen may show a warning. Attach the `.exe` to your GitHub release (next to `YapCord-<version>.zip`; the updater only uses the `.zip`).

### Sending the `.exe` (or the app) to friends

**Inside Yapper itself that is not possible.** Yapper only allows images, video, audio and `.zip`, `.txt` or `.pdf` files, and the limit is 10 MB (free) or 100 MB (Yapper Plus). The `.exe` is about 80 to 100 MB, so it does not fit in a message. That is a rule of Yapper itself (like Discord, which does not let `.exe` files through either) and not a bug in YapCord. YapCord does not try to get around it: UploadCompressor respects the limit, it does not switch it off.

What does work:

- **Share the installer `.exe` through a link**: put `YapCord-Installer-1.19.0.exe` on your GitHub release, Google Drive, OneDrive or Dropbox and send the link in Yapper. That is the easiest route: your friend only needs that one file, no Node.js or terminal required.
- **Send the small source zip** (`YapCord.zip`, about 200 KB; that fits well under 10 MB and `.zip` is allowed in Yapper, provided Yapper has it enabled for your account). Your friend needs Node.js installed and a terminal: unzip, then follow [Way 1](#way-1-inside-the-official-yapper-app-you-stay-logged-in) or [Way 2](#way-2-as-a-stand-alone-app) above.
- If you have **Yapper Plus** and the file is under 100 MB, you can put an `.exe` in a `.zip` and send that.

The `.exe` is not digitally signed: Windows SmartScreen may show a warning ("More info", then "Run anyway"), and some virus scanners react to unknown `.exe` files. Say so when you share it.

## Browser extension (Chrome / Edge / Brave)

If you use Yapper in the browser instead of the desktop app, a Manifest V3 extension puts the same plugin, theme and settings runtime straight into the page itself, on either domain Yapper serves from (`yapper.website` and `yapin.gg`, with or without `www.`) - no desktop app, no Node.js to run it, no logging in again (your browser's own Yapper session is untouched).

**Chrome, Edge and Brave for now** (anything Chromium-based, version 111 or newer; not Firefox).

### Installing it

1. Build it once (Node.js is only needed to run the build script - nothing is downloaded into the browser):
   ```
   npm run dist:extension
   ```
   That makes `dist\extension-stage` (the unpacked extension) and `dist\YapCord-Extension-1.19.0.zip`.
2. Open `chrome://extensions` (`edge://extensions`, or Brave's `brave://extensions`), turn on **Developer mode** (top right), click **Load unpacked**, and pick the `dist\extension-stage` folder (unzip `YapCord-Extension-1.19.0.zip` first if that's what you were sent).
3. Open or reload `yapper.website` or `yapin.gg`, whichever you use. The settings (gear icon) now have a **YapCord** section, exactly like in the app.

To get a newer version later: rebuild (`npm run dist:extension`) and click the reload icon on the extension's card in `chrome://extensions` - the extension does not update itself (see below).

### What's different from the desktop app

Same runtime, same plugins, themes and Custom CSS - just without anything that only exists inside an Electron window:

- **No app-only settings** (system tray, start with Windows, the own file picker for the **+** button, closing the separate Yapper desktop app, the custom screen-share picker). Those need Electron, so the **YapCord** page simply leaves that whole part of its Settings list out here - a short note explains why, there is no stand-in row or disabled switch anywhere.
- **No auto-update.** Unlike the app (which checks GitHub and updates itself in the background - see [Updating](#updating)), the extension never checks GitHub or updates itself; get a newer version the way you got this one (rebuild, or a new zip).
- **No Backup & Restore page.** Export/import of settings as a file uses the same native file access the app has, which isn't wired up for the extension yet.
- **Settings live in the browser**, not in `%APPDATA%\YapCord`: plugin on/off state and Custom CSS are kept in `localStorage` on whichever domain you're on (the same fallback the app itself already falls back to when it can't reach Electron, see [Limitations](#limitations-honest)). `localStorage` is per-domain, so `yapper.website` and `yapin.gg` each keep their own separate settings, separate from the app's own settings too - and clearing a site's browsing data in the browser clears that domain's copy.
- Everything else - every plugin that works by changing the page itself (which is almost all of them) - works exactly as it does in the app.

### Building it yourself

```
npm run dist:extension
```

`tools/build-extension.js` bundles `src/renderer/` - the exact files the desktop app uses, unchanged - into `injected.js` (`buildBundleForExtension()` in `src/main/bundle.js` is the only extension-specific code: it reads the initial settings from `localStorage` itself instead of the main process handing them over, since there is no main process here). It then copies `extension/manifest.json` and the icons into `dist\extension-stage` and zips it. The manifest declares exactly one content script (`injected.js`, running in the page's own JS world, at `document_start`) scoped to `yapper.website` and `yapin.gg` (with and without `www.`); nothing else is requested.

## Bookmarklet (any phone, iPhone included)

The extension above needs a browser that can load extensions, and no phone browser can - not Chrome on Android (it has no extension support at all), and not Safari on iPhone either (installing a real Safari Web Extension needs Xcode on a Mac, which the extension above doesn't need but a *mobile* one would). The bookmarklet sidesteps that: it's the exact same runtime, packaged as a `javascript:` link instead of a content script, so it can be saved as a plain bookmark and tapped - something literally every browser already supports.

### Installing it

```
npm run dist:bookmarklet
```

That writes `dist\YapCord-Bookmarklet.html` - open it (on the computer first is easiest) and follow the instructions on the page itself:

- **iPhone (the method that actually works well):** the Shortcuts app's **"Run JavaScript on Webpage"** action, added to the Share Sheet. The install page has the exact steps and a "Copy code" button for the script itself.
- **Any phone, the general method:** create the bookmark on a desktop browser (Chrome or Edge, signed in to the account that syncs to your phone), then open it from your phone's synced bookmarks while on `yapper.website`. Trying to save it directly from the phone works too in some browsers, but desktop-then-sync is the reliable route.

Either way: while on `yapper.website`, run it. The settings (gear icon) get a **YapCord** section, same as everywhere else. **You have to run it again every time you open a new tab or reload the page** - unlike an extension, a bookmarklet doesn't stay active.

### What's different from the extension

Same runtime (`buildBundleForBookmarklet()` in `src/main/bundle.js` is, again, the only bookmarklet-specific code - one line different from the extension's build, nothing else), with one real trade-off on top of what the extension already leaves out ([app-only settings](#whats-different-from-the-desktop-app), Updater, Backup & Restore - all the same here):

- **It runs after the page has already loaded**, not before, because a bookmarklet physically can't run any earlier than the tap that starts it. In practice that only matters for the very first moment of a fresh page load: NoTrack, for instance, only blocks requests from the tap onward, not the handful Yapper's own code may have already sent before you ran it. Everything that works by changing what's already on the page (which is almost everything - the Plugins page itself, themes, Custom CSS, message/UI plugins) works exactly the same, run early or late; this was checked directly (`test/e2e-bookmarklet.js` loads the real page fully, *then* runs the script, the same order a phone actually uses).
- **Tapping it again on the same tab is harmless** (it notices it already ran and does nothing), but it does not persist across a reload or a new tab the way an extension's content script does - you run it again each time.

### Building it yourself

```
npm run dist:bookmarklet
```

`tools/build-bookmarklet.js` takes the same bundle the extension uses and percent-encodes it whole into a `javascript:` URI (keeping every comment and newline intact, rather than squeezing the script onto one line by hand), then wraps that in a small install page with copy-to-clipboard and the Shortcuts steps.

## Opening the settings

Any of these:

- Yapper's **gear icon** (settings) → the left list now has a **YapCord** section;
- the **YapCord button** next to the gear at the bottom;
- shortcut **Ctrl + ,**;
- stand-alone app only: right-click the **tray icon** → *YapCord settings*.

The pages:

Styled after Vencord's own Settings modal: a banner, a **Quick Actions** grid and a plain Settings list on the main **YapCord** page, a ⓘ button on every plugin card instead of an "Authors"/links block, and a Local/Online split on the Themes page.

| Page | What you do there |
|---|---|
| **YapCord** | The home page: a **Quick Actions** grid (Edit Custom CSS, Reload YapCord, Open Settings Folder, Open Themes Folder), then a **Settings** list - "Enable Custom CSS", and in the stand-alone app close to tray, start with Windows, start minimized, spell checking, hardware acceleration, the own file picker and closing the Yapper app (inside the official Yapper app, or outside the app entirely, a short note explains why those aren't there instead). ## Updating

**YapCord → Updater** (inside the real app only — the browser extension and the bookmarklet have no update-checking of any kind, see [What's different](#whats-different-from-the-desktop-app)) shows the current status, a **Check for updates** button, **Update now**/**Restart now** once something is found, and two switches (**Automatically check for and install updates**, on by default; **Notify me when an update is ready**, on by default). In the background, every few hours, YapCord also looks for a newer version by itself and (in the Yapper app) installs it automatically; you only ever see a toast once a new version is actually ready, unless you turn that notification off. Two things are needed:

1. **A GitHub repository YapCord updates from**, set on the Updater page (`owner/repo`). It is already filled in for this build (`yapcord.updateRepo` in `package.json`), which is used until you set your own on the page. While no repository is set either way, nothing is checked.
2. **A newer version in that repository.** As the *Latest release*, the attachment `YapCord-<version>.zip` is used (a zip with the YapCord folder inside); without an attachment the source zip of that release, and without releases the `package.json` on the default branch. The package must be named `"name": "yapcord"`, have a **higher** version number than yours and contain the files the runtime needs; otherwise it is ignored. The repository must be public.

How it works:

- **In the Yapper app (Way 1):** the update is downloaded and unpacked next to your current version (`%APPDATA%\YapCord\runtime-next`). Nothing changes while Yapper is running. At the **next start of Yapper** the small start-up file switches over; if the new version does not start, it puts the previous one (`runtime-prev`) back. You see a message with a *Restart now* button when something is ready.
- **As a stand-alone app (Way 2):** it only checks and shows where you can download the new version; you install it yourself.
- **Once for an older install:** the start-up file in Yapper's folder comes from the installer. If you installed YapCord 1.3.0 or older, run the **installer of this version once** (or, from the source, `node tools\yapper-patch.js install`); after that new versions update themselves. (That start-up file itself is not replaced by updates; if that ever changes, the release will say so.)
- **Security, honestly:** an update is code that runs on your computer. Only `https` connections to GitHub are used, the package may be at most 30 MB and is checked (name, version, files, no paths outside the folder), but **whoever has write access to the repository decides what runs on your computer**. So only set a repository you trust. A Yapper update itself (the official app) has nothing to do with this.

## Plugins

Nothing is on by default: all 80 start **off** and you switch on whichever you want yourself. Switching one on or off only saves the choice — a **Restart required** notice with a **Reload** button then appears, and the change only takes effect once you use it. The full list with options is in [FEATURES.md](FEATURES.md#yapcord-plugins).

Forty-nine more things are **always on** instead: not a choice, not in this page at all, just part of YapCord for everyone — **ReadAllNotificationsButton**, **PinDMs**, **ChannelNotes**, **ScreenShareQuality**, **AvatarEffects**, **NameEffects**, **SmoothTransitions**, **MessageFX**, **DoubleTapReact**, **SlashModeration**, **FixCodeblockGap**, **ParticleFX**, **MotionSuite**, **UIPolish**, **OnboardingPolish**, **IdleVoiceControls**, **YapCordBadge**, **EmojiPreview**, **RoleReorderConfirm**, **SpellcheckGuard**, **RestartShortcut**, **EmojiPickerOrder**, **MoreQuickReactions**, **ScreenShareAudioToggle**, **MessageEncryption**, **SwipeNavigation**, **CallPing**, **CharacterCounter**, **FriendNicknames**, **HideChannels**, **HideMedia**, **ImageFilename**, **KeepCurrentChannel**, **MemberCount**, **NoMosaic**, **NoSystemBadge**, **NoTrack**, **PermissionsViewer**, **PreviewMessage**, **PushToTalk**, **ReplyPingDot**, **RoundedCorners**, **ServerInfo**, **ShikiCodeblocks**, **Unindent**, **UploadCompressor**, **UserVoiceShow**, **VoiceDownload** and **NoGifAds**. Options for the ones that have them (RoundedCorners' corner size, PushToTalk's key, and so on) live on a new **YapCord → Always-on** settings page — see below. What each plugin does is in [FEATURES.md](FEATURES.md#always-on-features) and in the "Good to know" / per-version notes below (several of those notes were written while they were still ordinary plugins; the behaviour they describe is unchanged, only the on/off switch is gone).

**New in 1.33.4: the Updater's "Check for updates" no longer fails with "GitHub answered 415" on a repo with no releases yet.** The 415 (Unsupported Media Type) came from always asking for `Accept: application/octet-stream` on the download step - the right header for a real release asset's own CDN link, but something GitHub's `/zipball/<branch>` API endpoint (used as a fallback for a repo with no releases, which is exactly what a freshly split-off repo like `YapCord-Windows` looks like at first) flatly refuses to answer at all. That header is now only sent for an actual release-asset download; the zipball fallback uses the normal default header instead, same as every other GitHub API call YapCord makes.

**New in 1.33.3: the Updater now defaults to the right per-platform GitHub repo on its own.** Since the project split from one `YapCord` repo into separate ones per platform (`YapCord-Windows`, `YapCord-Linux`, `YapCord-MacOS`, plus `YapCord-Browser`, `YapCord-Android` and `YapCord-IOS` for the ones that don't run this updater), the **YapCord → Updater** repo field now fills itself in correctly for whichever desktop platform you're on - Windows gets `YapCord-Windows`, Linux gets `YapCord-Linux`, macOS gets `YapCord-MacOS` - instead of still pointing everyone at the single old repo. Leaving the field blank keeps using that automatic default; typing your own `owner/repo` there still overrides it, same as before. The YapCord Installer's "only official place to get YapCord" link follows the same change, since it's always the Windows one.

**New in 1.33.2: every comment stripped from the source - no behaviour change.** Purely a code-cleanliness pass across all 230 `.js` files in the project (`src/`, `tools/`, `test/`, `installer/`, `extension/` - everywhere), including the public source itself: every `//` and `/* */` comment is gone, leaving pure code. Done with a tokenizer-based tool rather than regex, specifically so a `//` or `/*` sequence legitimately sitting inside a string, template literal or regex (like a URL or a path-matching pattern) is never mistaken for a comment and corrupted; every file was re-verified token-for-token against its original afterward to confirm nothing but comments and incidental blank lines changed. The full test suite (syntax, all 32 unit tests, and the non-browser e2e suites) passes unchanged.

**New in 1.33.1: "Add theme file" fixed on iPhone (and anywhere else without a real file system - Android, the browser extension).** Reported directly: adding a theme by pasting a link already worked everywhere, but the "Add theme file" button on the Themes page silently did nothing on an iPhone specifically. Root cause: the hidden `<input type="file">` this uses outside the desktop app (there's no OS file dialog to call there, so it reuses the browser's own file chooser the same way on every platform) was hidden with `display:none` - iOS Safari refuses to open the native file picker for a synthetic `.click()` on a file input that isn't actually laid out on the page at all, while Chrome/Android/desktop browsers don't mind. Fixed by keeping it off-screen instead (`position:fixed` + `opacity:0`, the same technique already used for the clipboard-copy fallback), which every browser treats as clickable. Local theme files, themes already added, and theme links are all unaffected - only the "Add theme file" button itself was broken, and only on iOS.

**New in 1.33.0: ChatExport removed (same usage-policy reason as 1.32.1), the three `.bat` files replaced by the plain `node tools\yapper-patch.js install`/`uninstall` commands they ran, and the Updater settings page is back.** **ChatExport** saved the messages already loaded in the open chat to a file - that is scraping/saving other people's messages under the same policy that removed ScheduleMessage and DoNotDisturbSchedule in 1.32.1 (see that note below), so it is gone the same way: the plugin file, its settings, and every current-state mention in this README and FEATURES.md (the e2e-v111.js mention from 1.11.0, when it was introduced, is left as a historical record, same as for the other two). Separately, `Install-in-Yapper.bat`, `Start-YapCord.bat` and `Uninstall-from-Yapper.bat` are removed from the source: each was a thin wrapper around a plain command (`node tools\yapper-patch.js install`, `npm install && npm start`, `node tools\yapper-patch.js uninstall`) that only existed to install Node.js through `winget` for someone without it - now that the **YapCord Installer** `.exe` (built with `npm run dist:installer`) is the real, no-Node-needed way to get YapCord into Yapper, and anyone building from source already has Node.js to run `npm`, the three scripts were redundant cruft; every step they used to automate is in [Quick start](#quick-start-windows) as a plain command instead. Last, the **Updater** settings page is back (`YapCord → Updater`): a status line, **Check for updates**, **Update now**/**Restart now**, and the `updater.repo`/`updater.auto`/`updater.notify` settings as an actual repo field and two switches instead of settings you could only change by hand-editing `settings.json`. Nothing about how updating itself works changed (still `src/main/updater.js`, still the same background timer) - this is only a UI for settings and actions that already existed; see [Updating](#updating).

**New in 1.32.1: ScheduleMessage and DoNotDisturbSchedule removed, to stay inside a usage policy Yapper shared for third-party clients.** That policy allows look-and-feel/QoL changes but explicitly bans "automating your account (no auto messages, reactions, joins, or clicking things for you)". **ScheduleMessage** sent a message by itself at a later time through Yapper's own send, with nobody there to press Enter at that moment - a textbook auto message under that rule. **DoNotDisturbSchedule** automatically flipped your status on a timer - a smaller case of the same thing (an automated action on your account, not something you did yourself in the moment), removed for the same reason rather than left in a grey area. Both are gone outright: the plugin files, their settings pages, and every current-state mention in this README and FEATURES.md. The e2e test files from the versions that introduced them (1.9.0, 1.11.0) still mention them by name - that is a historical record of what those tests covered at the time, not a sign they are still built.

### Writing your own plugin

Create a file in `src\renderer\plugins\` with **the same name as the plugin**, for example `BigComposer.js`:

```js
(function () {
  YM.definePlugin({
    name: 'BigComposer',
    description: 'Makes the text in the message box bigger.',
    authors: ['you'],
    tags: ['Appearance'],
    start(ctx) {
      ctx.css('.composer textarea { font-size: 18px !important; }');
    },
  });
})();
```

Restart the app and the plugin is in the list (off). Everything you create in `ctx` (`css`, `watch`, `on`, `interval`, `timeout`, `cleanup`) is cleaned up automatically when the plugin is switched off. Also available: `YM.Store` (Yapper's own state), `YM.messages` (messages on screen), `YM.net` (WebSocket and fetch hooks), `YM.patches` (Vencord-like patches) and `YM.finder` (finding Yapper's modules). Use an existing plugin in `src\renderer\plugins\` as an example; `npm test` checks that your plugin is defined properly.

For the `.exe` files: new plugins must be in there *before* you run `npm run dist` / `npm run dist:installer`.

## Themes and Custom CSS

A theme is a plain `.css` file in `%APPDATA%\YapCord\themes`. The first lines may contain Vencord-style metadata:

```css
/**
 * @name My theme
 * @author Me
 * @description Darker and calmer
 * @version 1.0.0
 */
:root { --bg: #0b0c10; }
```

New or changed files show up / take effect immediately (the folder is watched). **22 themes** are included (Dracula, Nord, Tokyo Night, Catppuccin Mocha/Latte, Gruvbox, Solarized, One Dark, Rosé Pine, Synthwave, Paper, Mint Light, High Contrast and Amoled, among others). They are our own themes based on well-known colour palettes: BetterDiscord themes cannot be used directly because they use Discord's class names and Yapper has different ones. They are put in that folder; if you delete one it does not come back, and with a new version only the *new* themes are added. Yapper's colours are CSS variables; look in DevTools at `:root` to see which ones.

## Where is my data?

Everything is in `%APPDATA%\YapCord` (paste that in the Explorer address bar):

| Path | Contents |
|---|---|
| `settings\settings.json` | Settings and plugin options |
| `settings\quickCss.css` | Your Custom CSS |
| `themes\` | Your themes |
| `logs\main.log` | The app's log (handy for problems) |

The app also keeps **your Yapper login session** (cookies, local storage) in that same folder. So **never share that folder**, just like you would not share a Yapper profile folder. A backup via the *Backup & Restore* page contains no login session.

If you run YapCord inside the official Yapper app (Way 1), your login session simply stays in Yapper's own folder `%APPDATA%\Yapper`; `%APPDATA%\YapCord` then only holds your settings, themes, logs and the copied YapCord files (`runtime\`).

Removing: with Way 1, first click Uninstall in the installer (or, from the source, run `node tools\yapper-patch.js uninstall`). With Way 2, close the app and delete the program folder. If you also want to lose your settings, delete `%APPDATA%\YapCord`.

## Troubleshooting

- **Channels, server groups and DMs stay empty for ~30 seconds after every restart (everyone shows offline except you):** since 1.9.1, Windows proxy auto-detection is skipped by default - on some Windows machines, Chromium's own proxy auto-detection (WPAD) otherwise hangs for 20-30 seconds on the first network calls of every launch, even though the window itself opens fine. Since 1.22.0 this is always on, with no setting to turn it off any more (it was a settings toggle before that, but almost nobody wants it off, and the rare exception - YapCord specifically needing your own proxy server to reach the internet - can still set `window.skipProxyDetection` to `false` by hand in `settings\settings.json`).
- **White screen or "offline" page:** check your internet; the app tries to load yapper.website.
- **A plugin does nothing after a Yapper update:** YapCord finds parts of Yapper by name. If Yapper changes a lot in its code, a plugin can break for a while. Open DevTools (see below) and run `copy(JSON.stringify(await window.YapperMod.diagnostics(), null, 2))` to copy a diagnostics report, and send that along if you ask for help. It contains version numbers, which hooks work and your plugin settings (for example your TextReplace rules), but no messages, passwords or tokens; feel free to look at it first.
- **Console/DevTools:** menu *View → Toggle Developer Tools* (press **Alt** to show the menu bar) or Ctrl+Shift+I. With the *ConsoleShortcuts* plugin you get handy commands like `ymState()` and `ymPlugins`.
- **Reset everything:** close the app and rename `%APPDATA%\YapCord\settings`.
- **Yapper no longer starts after installing (Way 1):** click *Uninstall* in the installer, or run `node tools\yapper-patch.js uninstall` from the source. If that does not work, rename `_app.asar` back to `app.asar` in Yapper's `resources` folder and delete the folder `app`. Or reinstall Yapper; your data is in `%APPDATA%\Yapper`.
- **"Yapper is still running" when installing:** quit Yapper through the system tray (*Quit*), or end the process *Yapper* in Task Manager, and try again.
- **There is no YapCord section in the settings (Way 1):** look in `%APPDATA%\YapCord\logs\main.log`. If it says `running inside Yapper`, the connection works and the cause is the page (send the diagnostics file). If there is nothing, the patch is gone (for example after a Yapper update): install again.

## Limitations (honest)

- **Not tested on the real yapper.website.** My development environment could not reach that site. I tested the runtime against a copy of Yapper's real, built code and a rebuilt page with the same structure, and the Electron side with a simulated Electron. The very first start in the real app is therefore also the real test; if something does not work, send the diagnostics file.
- **Yapper updates** can break plugins (see above).
- **Vencord plugins do not work 1-to-1**; they have to be rewritten for Yapper. See [FEATURES.md](FEATURES.md).
- **Way 1 (inside the Yapper app) was rebuilt and tested with a simulated Electron and a fake Yapper install folder, not on a real Windows install.** The installer was checked against Yapper 1.0.0's real `app.asar` (name, version, structure). What I could not check: whether your Yapper version has the Electron protections on (the installer reports that) and whether Yapper's updater leaves the patch in place (probably not, see above).
- **The installer program has not been built and started as a real `.exe`.** Its logic (finding, installing, repairing, uninstalling, starting Yapper) and its window are tested, but building with `electron-builder` and running it in Electron on Windows are not. If building or starting fails, send the error message.
- **The updater, the app icon and the Layout page were tested with simulated environments** (a local GitHub imitation, a simulated Electron, Yapper-like columns), not on a real Windows install with a real GitHub release. Switching the start-up file on an update was tested with a fake Yapper folder.
- **Layout:** Yapper has no member list to move; the columns are servers, channels/DMs and chat. On a narrow window (under 761 px, Yapper's own one-column view) Yapper's own layout stays. The zoom of the whole app only works in the app.
- The stand-alone app's `.exe` is not signed. The stand-alone app does check for updates in the background, but does not install them itself (see [Updating](#updating)).
- **The browser extension is not published anywhere** (no Chrome Web Store listing) - "Load unpacked" only, and like everything else it was tested against a copy of Yapper's built code and a real Chromium (Playwright), not against the real `yapper.website`.
- **Android: a patched build of the real Yapper app exists, but it's not a from-scratch YapCord app and comes with real trade-offs.** It's made by decompiling a real, user-provided Yapper Android APK with `apktool`, adding one small bridge method next to the app's own existing `injectNotificationBridge()` call so it runs the same YapCord bundle the bookmarklet/extension use, then rebuilding and re-signing it (see `YAPCORD-MOBILE-README.md` alongside that project for the exact patch and how to redo it). Real limits worth knowing: it's a decompile, not the original Kotlin source, so there's no way back to real class names or comments; it has to be signed with a throwaway debug key since only Yapper's own developers have the real one, so Android treats it as a different app and installing it means uninstalling the original Yapper app first (and losing its locally-stored data - your account and messages on Yapper's own servers are unaffected); and it has only ever been checked statically (the dex disassembles back to exactly what was written, a full decompile-of-the-rebuild round trip confirms the patch survived) - there has never been a real device or emulator available here to actually install and run it. A fresh, from-scratch native Android app (not a patch of an existing one) was not attempted for the same reason: no device or emulator to check it actually starts, and this project does not ship things unchecked.
- **No real iPhone app.** A native iPhone app or a real Safari Web Extension needs Xcode on a Mac and, for anything beyond a 7-day personal sideload, an Apple Developer account - tooling a Windows/Linux setup like this one cannot provide at all. The [bookmarklet](#bookmarklet-any-phone-iphone-included) is what actually reaches iPhone, and it was checked the same way everything else here is.

see 1.15.0 above), `e2e-recentemojis.js` for RecentEmojis against Yapper's real emoji-picker markup (standard and custom emoji cells, the Recent section, insertion, the right-click-to-remove and the 24-item cap), `e2e-ptt.js` for PushToTalk, `e2e-hidechannels.js` for HideChannels, `e2e-autotranslate.js` for AutoTranslate, `e2e-uipolish.js` for the small visual touches (including the "reduce motion" check), `e2e-onboardingpolish.js` for the clearer Server Settings → Onboarding page, `e2e-dmavatars.js` for the sender-avatar pills in the server rail, `e2e-idlevoicecontrols.js` for the idle mic/deafen pair and its two chevron dropdowns in the account bar, `e2e-core.js` with regression tests for bugs found earlier, `e2e-extension.js` for the real browser extension - built fresh and loaded unpacked into Chromium with Playwright's `--load-extension`, exactly as `chrome://extensions` would load it, to check the content script, the localStorage-only settings and the hidden App page end to end, and `e2e-bookmarklet.js` for the bookmarklet - the cached page is allowed to load completely on its own first, and only then is the decoded script run, the same order a phone actually uses, to check that boot order honestly rather than assume it). They only start if you set `YM_CACHE_DIR` to such a copy (see `test\lib\site.js`) and are meant for people who develop YapCord further.

## Folder layout

```
src/main/        Electron main process: window, tray, network filter (NoTrack), IPC, backup, screen sharing
src/main/inject.js  YapCord inside the official Yapper app (Way 1)
src/main/updater.js, unzip.js   The updater (GitHub) and a zip reader without extra packages
src/main/appicon.js, trayicon.js   Own app and tray icon
installer/       The installer window (Electron) and its logic (core.js)
tools/           yapper-patch.js: installs/removes YapCord in the Yapper app; build-installer.js builds the installer .exe; build-extension.js builds the browser extension
src/preload/     Bridge between app and page (only on yapper.website, only the top frame)
src/renderer/    The runtime that is put into the page: hooks, settings UI, plugin manager
src/renderer/plugins/   One file per plugin
extension/       The browser extension (Chrome/Edge/Brave): manifest.json + icons; tools/build-extension.js builds injected.js
tools/build-bookmarklet.js   Builds the bookmarklet (any phone, iPhone included) - the install page + the javascript: URI
themes/          Bundled example themes
test/            Tests
build/           App icon
```
